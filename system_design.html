System Design

System design is the process of defining the architecture, components, and relationships of a system to make it robust and reliable.

Availability and Scalability

Availability and scalability are key aspects of system design. They ensure that the system can handle a large number of users and requests without downtime.

  • Scalability: capacity to handle data or users.
    • Horizontal scaling: adding more servers or nodes.
    • Vertical scaling: adding more resources to existing servers.
  • Availability: How long a system is available and able to respond to requests.
    • availability = available_time real_time

How to handle horizontal scaling?

With a Load Balancer, it distribute the requests between servers using differents algorithms like:

  • Round Robin: For turns without care the loads of servers.
  • Least-Connectios: Distribute to servers with short requests, it's useful for distinguishing "types of requests" and balancing them accordingly.

Data Base

To store the user data, we need a physical or cloud placement, the data can be stored in differents formats.

  • SQL: Data is stored in tables with relationships, the data is structured, and the transactions follow de ACID principles.
  • NoSQL: Flex models, better for horizontal scaling and differents types of data.

What is ACID?

  • Atomicity: Occurr when a transaction is completed, all changes are either applied or not.
  • Consistency: The database remains in a consistent state after a transaction.
  • Isolation: The transactions are isolated from each other, so changes made by one transaction do not affect others, most commonly in concurrent transactions.
  • Durability: The changes made by a transaction are permanent, even in the event of a system failure.
