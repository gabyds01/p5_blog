System Design

System design is the process of defining the architecture, components, and relationships of a system to make it robust and reliable.

Availability and Scalability

Availability and scalability are key aspects of system design. They ensure that the system can handle a large number of users and requests without downtime.

  • Scalability: The capacity to handle growing data or traffic.
    • Horizontal scaling: Adding more servers or nodes.
    • Vertical scaling: Adding more resources to an existing server.
  • Availability: The proportion of time a system remains operational and responsive to requests.
    • availability = available_time real_time

How to handle horizontal scaling?

A Load Balancer distributes requests across servers using different algorithms, such as:

  • Round Robin: Distributes requests sequentially, regardless of server load.
  • Least Connections: Directs requests to the server with the fewest active connections, useful for handling varying request workloads.

Database

To store user data, we rely on physical or cloud storage, where data can be structured in different formats:

  • SQL: Data is structured in relational tables, and transactions follow the ACID principles.
  • NoSQL: Flexible data models, optimized for horizontal scaling and diverse data types.

What is ACID?

  • Atomicity: Guarantees that all operations within a transaction either succeed completely or fail entirely.
  • Consistency: Ensures the database remains in a valid state before and after any transaction.
  • Isolation: Ensures concurrent transactions execute independently without interfering with each other.
  • Durability: Guarantees that committed transaction data is saved permanently, even in the event of a system failure.
